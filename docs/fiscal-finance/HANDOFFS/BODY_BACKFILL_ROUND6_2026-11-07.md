## 一、先纠一个自己的错：陕西那个"死选择器"是我看错了

上一轮我写"`bodyPolicies` 的 `.my_doccontent .TRS_Editor` 在页面上匹配数为 0，是死选择器"。**这个判断错了，错在检查方法。**

我用 `grep 'class="TRS_Editor"'` 去数，但陕西页面写的是**不带引号**的：

```html
<div class=TRS_Editor>
```

带引号 grep 自然是 0。用 cheerio 正确加载后，`.my_doccontent .TRS_Editor` 是命中的——只是容器里嵌了一个 `<style>` 块，543 字 CSS 混在文本里，把"正文"撑成 942 字又被 1500 字地板判不合格。

去掉 style 后真实正文 398–900 字，是干净的文章内容。

**教训：数元素必须用解析器，不能 grep 字符串。**

### 为什么不上 OCR

查过了：容器和本机都**没有任何 PDF 渲染工具**（pdftoppm / mutool / gs / pdfimages 全无），代码里也没有 OCR 实现。要 OCR 就得引入渲染引擎 + 识别模型，成本远超这 4 篇债券发行公告的编辑价值——按已确认口径，单期债券发行本来就只进"全部动态"。

那篇 102 页的也不该硬提上限：`MAX_PAGES = 40` 配套 10 秒超时，102 页必然超时并吃掉内存。
